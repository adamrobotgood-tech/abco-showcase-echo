abcomedia.net is unreachable over HTTPS.

Port 80 answers and 301-redirects every visitor to HTTPS. Port 443 accepts the TCP connection, then closes it before presenting any certificate, on TLS 1.2 and 1.3, with and without SNI. In practice, every browser that loads the site ends at ERR_CONNECTION_CLOSED. Nginx is running, DNS is fine, mail is separate. The fault is almost certainly the TLS layer on the VPS.

Diagnosis, ranked by fit to the evidence

MOST LIKELY

No working listen 443 ssl block for abcomedia.net. The default TLS server rejects the handshake.

Nginx is clearly alive (port 80 answers). When no HTTPS server block matches and the default one is set to ssl_reject_handshake on, nginx closes the connection with no certificate. That's exactly what we see. Typical causes: certbot never finished, the site's sites-enabled symlink was removed, or the config was rewritten without its SSL half.

POSSIBLE

Something other than nginx owns port 443

A container, panel proxy, or second web server could bind :443, accept TCP, and drop the handshake. ss -ltnp answers this in one command.

LESS LIKELY

Firewall or upstream filter interfering after ClientHello

The TCP handshake completes and the drop is identical across protocol versions, which points to an application-layer cause rather than a network block. Rule it out last.

fix · run on the VPS
# 1. Who owns 443?
sudo ss -ltnp '( sport = :443 )'

# 2. What does nginx think it serves?
sudo nginx -T 2>/dev/null | grep -nE \
  'listen .*443|server_name|ssl_certificate|ssl_reject'

# 3. Does a cert exist?
sudo ls -l /etc/letsencrypt/live/abcomedia.net/

# 4. Issue / reinstall and wire into nginx
sudo certbot --nginx -d abcomedia.net -d www.abcomedia.net

# 5. Validate and reload
sudo nginx -t && sudo systemctl reload nginx
verify · run from anywhere
# Expect: 200/301 over HTTPS, valid chain
curl -sSI https://abcomedia.net
curl -sSI https://www.abcomedia.net

# Expect: subject + notAfter ~90 days out
openssl s_client -connect abcomedia.net:443 \
  -servername abcomedia.net </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates

# Renewal must be automatic, not heroic
sudo certbot renew --dry-run

02 / Capture

No screenshot. On purpose.

There was nothing to capture: the browser and curl both stopped at the TLS handshake. We won't put a mockup in a report and call it a screenshot. When HTTPS is back, Echo re-runs and adds real full-page captures at desktop and mobile sizes.

What we did capture
  • Brand line: "ABCO // Edit. Anything." came back from a cached fetch of the homepage. It's the only on-page text available.
  • Stack fingerprint: nginx 1.24.0 on Ubuntu, a self-managed Hostinger VPS (srv1348401.hstgr.cloud). Not shared hosting.
  • DNS posture: Hostinger nameservers (dns-parking.com), www as a CNAME to the apex, no IPv6, no CAA.
  • Certificate history: the certificate-transparency lookup (crt.sh) returned a 502 during this run, so past certificates aren't confirmed. Flagged for the re-run.
